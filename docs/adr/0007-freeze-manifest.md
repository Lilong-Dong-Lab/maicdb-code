# Freeze manifest: a code-side pinned input contract

The loader's freeze enforcement was a git pathspec diff (`git diff
tag..HEAD -- data/ configs/` with two exclusion globs). It had three
structural weaknesses. First, it proved only *tree-level* sameness along
the tag→HEAD range at diff time; the loader could not state, as data, what
it requires — the requirement lived in git invocation, not in an artifact.
Second, the pinned constants (freeze tag, freeze epoch, schema version,
conservation counts) lived in `src/maicdb/loader.py`, so every retarget
edited loader code to say what is true of the vault — loader churn for a
pure input change. Third, nothing chained the published artifact back to
its input: `db/load-manifest.json` recorded counts, but nothing bound the
counted bytes to a named, hash-pinned set. Decided 2026-11-16
(architecture-review candidate 3, PR B; grilling session of 2026-11-15).

## Considered Options

- **Code-side freeze manifest, closed-set hash inventory (chosen)** —
  `db/freeze-manifest.json` pins identity + per-file sha256 + conservation
  counts; generated by `scripts/write-freeze-manifest.py` at each
  retarget, following the census-snapshot precedent (generated, committed,
  regenerable, never hand-edited). The loader hash-checks every load
  against it, fail-closed (missing/extra/changed file → RuntimeError).
  Constants move into the manifest; loader code stops changing at
  retargets.
- **Vault-side manifest** (the vault describes its own freezes) — rejected:
  the vault is private, so a self-describing vault has no consumer besides
  this repo; it would also make the vault repo's procedure part of the
  contract when only its content is.
- **Keep the pathspec diff, add the constants migration only** — rejected:
  the diff is tree-state machinery where a data file is clearer, and it
  cannot work in shallow clones (no deep history → no tag→HEAD diff).
- **Extend `db/load-manifest.json` instead** — rejected: the load manifest
  is the loader's OUTPUT record; the input contract belongs upstream of
  the load so it can be checked before a single row is transformed. The
  two are chained instead (see Consequences).

## Consequences

**Manifest content (normative).** `db/freeze-manifest.json` carries:
`freeze_tag` (the vault tag), `vault_head` (the tag's commit — the freeze
point, never the loading checkout's HEAD, which may sit on report-only
descendants), `freeze_date` (the declared freeze epoch — a human
declaration the vault cannot derive; data-v1.1 and data-v1.2 share
2026-11-08), `schema_version` (the formal-schema version the code
implements), `rows_total` + `rows_per_layer` (vault-extraction facts),
`files` (closed-set sha256 map), and `counts` (the loader routing counts,
filled by the generator's dry load — routing is a loader fact, which is
why `vault.py` must not import `loader`).

**Blob bytes, not working-tree bytes.** Hashes are computed over
`git cat-file blob <rev>:<path>` — the tag's blobs when building, HEAD's
blobs when checking. Reason: the vault carries git-LFS files
(`data/piezo1/structures/experimental/human/8YEZ.pdb`); the same commit
holds a 132-byte pointer in one checkout and the smudged 2.97 MB payload
in another, so working-tree hashing is checkout-dependent (found in this
PR's first suite run). For LFS paths the pinned pointer's embedded sha256
oid still pins the payload.

**Enforcement (normative).** `FrozenVault.verify` keeps its git gates
(clean tracked tree, tag resolves, HEAD descends from the tag) and
REPLACES the pathspec diff with: manifest tag must equal the required tag;
manifest `vault_head` must equal the tag's resolution (re-tagging a
freeze tag with consumers is forbidden); every inventoried file's HEAD
blob must match (changed content → new tagged release); no extra
frozen-surface files (new frozen content → new tag + regenerated
manifest). Untracked scratch files stay tolerated (the inventory is
tracked-files-only — the 47-file-incident semantics). Shallow clones work
(no history traversal, only blob reads). `require_tag=None` retains the
no-freeze-check probe semantics (hash check included).

**Chain.** `db/load-manifest.json` gains `freeze_manifest_sha256` (sha256
of the freeze manifest's bytes), and `census.manifest_anchor_problems`
extends: the declared hash must match the actual bytes. Chain: db rows →
load manifest → freeze manifest → vault blob bytes. One regenerated
freeze manifest therefore invalidates the load manifest until the next
load re-records it — intended: the artifacts move together at retargets.

**Retarget recipe.** Vault merge → tag → `scripts/write-freeze-manifest.py
--tag data-vN.N --freeze-date <declared> --schema-version <v>` → load +
regenerate census snapshot. Loader constants are gone from
`src/maicdb/loader.py`; a retarget no longer edits loader code.

**Relation to ADR-0006.** Stage 2 of that ADR (previous-manifest id
lookup at first public release) reads the LOAD manifest of the previous
release; this ADR adds the freeze manifest as a distinct document. No
conflict: identity stays per-release until that trigger fires, and this
ADR's manifest records exactly the freeze identity that trigger will
want.
