## Detailed findings

### Q1 — Static site generators on Cloudflare

**F1.1 — Pages has official SSG framework guides.** The [Pages framework guides index](https://developers.cloudflare.com/pages/framework-guides/) (updated 2026-08-21) lists per-framework deploy guides for: Analog, Angular, **Astro**, Blazor, Brunch, **Docusaurus**, Elder.js, Eleventy, Ember, Gatsby, Gridsome, Hexo, Hono, **Hugo**, Jekyll, **MkDocs**, **Next.js** (with a separate "[deploy a static site built using Next.js](https://developers.cloudflare.com/pages/framework-guides/nextjs/deploy-a-static-nextjs-site/)" guide), Nuxt, Pelican, Preact, Qwik, React, Remix, SolidStart, **Sphinx**, "Static HTML" (deploy-anything), SvelteKit, **VitePress**, Vue, Zola. Every SSG named in Q1 has an official Pages guide.

**F1.2 — Two deploy mechanisms on Pages.** The [Pages overview](https://developers.cloudflare.com/pages/) (updated 2026-08-25): "Deploy your Pages project by connecting to your Git provider, uploading prebuilt assets directly to Pages with Direct Upload or using C3 from the command line." The Pages docs index describes the pieces: [Build configuration](https://developers.cloudflare.com/pages/configuration/build-configuration/) — "Set build commands, output directories, and framework presets for Cloudflare Pages projects" (this is the build-pipeline preset mechanism); [Direct Upload](https://developers.cloudflare.com/pages/get-started/direct-upload/) — "Upload your prebuilt assets to Pages and deploy them via the Wrangler CLI or the Cloudflare dashboard" (`wrangler pages deploy`). Both are current, documented paths.

**F1.3 — Docs restructure during 2026.** The older URL `https://developers.cloudflare.com/pages/configuration/framework-configs/` returns 404 as of 2026-11-02. Per-framework preset documentation now lives under `pages/framework-guides/` and `pages/configuration/build-configuration/`. Any ADR citing Cloudflare docs should cite those paths.

**F1.4 — Workers also host SSG output (Workers with static assets).** The [Workers Static Assets page](https://developers.cloudflare.com/workers/static-assets/) (updated 2026-10-12): assets are uploaded as part of the Worker deployment ("Cloudflare deploys both your Worker code and your static assets in a single operation"), configured by `assets.directory` in the Wrangler config. The [SSG routing page](https://developers.cloudflare.com/workers/static-assets/routing/static-site-generation/) documents deploying prerendered/SSG applications with `not_found_handling` and `html_handling` options, and names Gatsby and Docusaurus. The [Workers framework guides index](https://developers.cloudflare.com/workers/framework-guides/) (updated 2026-07-03) covers Astro, Docusaurus, Gatsby, Next.js (OpenNext), and more — but has no Hugo/MkDocs/Sphinx/VitePress-specific guides; for those, the mechanism is generic: build anywhere, point `assets.directory` at the output. A Worker script is optional when only serving assets.

**F1.5 — Convergence, not deprecation.** The primary announcement is ["Bringing a unified developer experience to Cloudflare Workers and Pages"](https://blog.cloudflare.com/pages-and-workers-are-converging-into-one-experience) (published 2023-05-17, per page metadata): "Pages and Workers will be joining forces into one singular product experience", to be executed "over the next year", with the commitment that "Existing projects on both Pages and Workers will continue to work without users needing to lift a finger." Supporting evidence that this remains the posture:
- The ["Migrate from Pages to Workers" guide](https://developers.cloudflare.com/workers/static-assets/migration-guides/migrate-from-pages/) (updated 2026-10-12) exists and frames Workers as the broader platform ("Workers has a distinctly broader set of features available to it, including Durable Objects, Cron Triggers, and more comprehensive Observability") with a full compatibility matrix.
- Pages docs remain maintained: overview updated 2026-08-25, framework guides updated 2026-08-21. No deprecation, sunset date, or forced-migration notice appears on any page checked.
- A frequently-cited blog slug `blog.cloudflare.com/future-of-pages-and-workers` returns 404; no replacement primary announcement of that nature was found in searches on 2026-11-02.

**F1.6 — "New static projects → Workers": direction is clear, the explicit sentence is not found.** UNVERIFIED as a doc-quoted statement. What the primary sources do show: the static-assets home page's "Start from CLI" scaffolds a Worker (`npm create cloudflare@latest`); the migration guide moves Pages users to Workers; Workers gets the new features (Vite plugin, previews, gradual deployments — items marked ❌ for Pages in the compatibility matrix). Third-party posts claim Pages "will eventually be deprecated", but no Cloudflare primary source says so. Assessment: Cloudflare's investment is in Workers; Pages is in maintenance-plus mode with no announced end date.

### Q2 — FastAPI on Cloudflare Workers

**F2.1 — Status: GA, on Pyodide.** The [GA announcement](https://blog.cloudflare.com/python-workers-ga) (published 2026-09-21): "Today, Python Workers are now generally available (GA)... Python is now a first-class, fully supported language on the Cloudflare Developer Platform." It also states the runtime basis: "By using Pyodide, we were able to quickly support a wide range of Python applications" (Pyodide = CPython compiled to WebAssembly). The [Python Workers docs](https://developers.cloudflare.com/workers/languages/python/) (updated 2026-09-17) describe a "first-class Python experience" with FastAPI, Langchain, and Pydantic called out by name, and the `pywrangler` CLI (`uvx --from workers-py pywrangler init/dev/deploy`) as the toolchain.

**F2.2 — Python version.** PARTIAL. Doc-quoted facts: docs examples pin `requires-python = ">=3.13"` ([packages](https://developers.cloudflare.com/workers/languages/python/packages/), [FastAPI page](https://developers.cloudflare.com/workers/languages/python/packages/fastapi/)); "A new version of Python is released every year in August, and a new version of Pyodide is released six (6) months later. When this new version of Pyodide is published, we will add it to Workers by gating it behind a Compatibility Flag" ([How Python Workers Work](https://developers.cloudflare.com/workers/languages/python/how-python-workers-work/)). The exact Pyodide/Python version currently served per compatibility date is not published on any page checked. Pyodide's stable distribution is versioned 314.0.7 (the project switched from 0.x versioning to 314.x in its version list); the mapping of that number to a CPython minor version is not stated on the pages captured. UNVERIFIED beyond the above.

**F2.3 — ASGI/FastAPI support.** CONFIRMED. The [official FastAPI page](https://developers.cloudflare.com/workers/languages/python/packages/fastapi/) (updated 2026-08-28): "FastAPI is supported in Python Workers... The Python Workers provide an ASGI server that you can use directly in your Python Worker" — `from workers import asgi; Default = asgi.entrypoint(app)`, with `compatibility_flags: ["python_workers"]` in the Wrangler config. The GA blog generalizes: the `workers.asgi` and `workers.wsgi` connectors "can be used not only with FastAPI, Django, or Flask, but with any Python web framework that uses the WSGI or ASGI interface." FastAPI and Flask are listed under "APIs" in the [Workers framework guides](https://developers.cloudflare.com/workers/framework-guides/).

**F2.4 — Package constraints.** The [packages docs](https://developers.cloudflare.com/workers/languages/python/packages/) (updated 2026-09-18): "Python Workers support pure and PyEmscripten (PEP 783) Python packages on PyPI. Additionally, Python Workers support packages that are included in Pyodide." And on compiled-extension availability: "WebAssembly support for Python packages is still in early stages, and some packages may not yet be available as PyEmscripten wheels on PyPI." So a package with Rust/C extensions must either (a) publish PyEmscripten wheels on PyPI (PEP 783), or (b) be built into the Pyodide distribution. `pywrangler deploy` bundles `pyproject.toml` dependencies into the Worker automatically.

**Pyodide distribution check** ([packages-in-pyodide](https://pyodide.org/en/stable/usage/packages-in-pyodide.html), stable 314.0.7, fetched 2026-11-02):

| Package | In Pyodide distro? | Version in distro |
|---|---|---|
| fastapi | Yes | 0.136.1 |
| pydantic | Yes | 2.12.5 |
| pydantic_core | Yes | 2.41.5 |
| sqlalchemy | Yes | 2.0.48 |
| pyyaml | Yes | 6.0.3 |
| uvicorn | **No** | absent from the list |

Uvicorn's absence is not a blocker: the Workers platform is the server, and `workers.asgi` is the adapter — the FastAPI docs page makes this explicit ("In Cloudflare Workers, the Workers platform itself serves as the web server", GA blog). Pydantic-core (Rust) and SQLAlchemy (C) being in the Pyodide distribution is exactly the mechanism that makes FastAPI+pydantic+sqlalchemy deployable.

**F2.5 — Storage: reading a 3 MB SQLite at request time.** Componentwise CONFIRMED; the composition is inference.

- **Full stdlib minus an exclusion list.** The [Python stdlib page](https://developers.cloudflare.com/workers/languages/python/stdlib/) (updated 2026-06-22): "The full Python Standard Library is available in Python Workers, with the following exceptions" — curses, dbm, ensurepip, fcntl, grp, idlelib, lib2to3, msvcrt, pwd, resource, syslog, termios, tkinter, turtle, turtledemo, venv, winreg, winsound (plus non-functional multiprocessing/threading). `sqlite3` is not on the exclusion list, so the page's own claim makes it available. Caveat: no current Cloudflare or Pyodide stable page I captured shows a worked `import sqlite3` example; confidence in the import itself is high (exclusion-list logic) but untested here.
- **Ephemeral in-memory filesystem.** Same page: "Python Workers have access to an ephemeral, in-memory filesystem. You can read and write files using standard Python file I/O... but all data is lost when the Worker isolate is destroyed. The filesystem is not shared between different isolate instances."
- **Assets are readable from Python at request time.** The static-assets page shows a Python Worker calling `await self.env.ASSETS.fetch(request)`, and the FastAPI page shows fetching an asset by URL and reading `await resp.bytes()`. Static asset limits: individual file size 25 MiB (both plans); 20,000 files per Worker version (Free) / 100,000 (Paid); requests to static assets are free and unlimited ([Workers limits](https://developers.cloudflare.com/workers/platform/limits/), [billing](https://developers.cloudflare.com/workers/static-assets/billing-and-limitations/)). A 3 MB SQLite file fits the 25 MiB per-file cap.
- **Inference (agent assessment, not doc-quoted):** shipping `maicdb.sqlite` as an asset, fetching it via the ASSETS binding, and opening it from bytes (or via the in-memory filesystem) with `sqlite3` is doc-supported at every step but is not demonstrated end-to-end in any page captured. Costs to validate: per-isolate load (the deploy-time snapshot covers top-level imports, not per-request asset fetches — [How Python Workers Work](https://developers.cloudflare.com/workers/languages/python/how-python-workers-work/)), the 128 MB isolate memory cap, and 10 ms CPU on the Free plan.
- **Platform-native alternatives.** D1: max database size 500 MB (Free) / 10 GB (Paid); 5 GB total account storage on Free; 10 databases on Free ([D1 limits](https://developers.cloudflare.com/d1/platform/limits/), updated 2026-10-30). Durable Objects with SQLite backend: "Workers Free plan can only create and access SQLite-backed Durable Objects" ([pricing](https://developers.cloudflare.com/workers/platform/pricing/)). D1 reads on Free are 5 million rows/day ([pricing](https://developers.cloudflare.com/workers/platform/pricing/)).

**F2.6 — Plan and compute limits** ([Workers limits](https://developers.cloudflare.com/workers/platform/limits/), [pricing](https://developers.cloudflare.com/workers/platform/pricing/)):

| Limit | Workers Free | Workers Paid |
|---|---|---|
| Requests | 100,000 / day | 10 M/month included, then $0.30/M |
| Static asset requests | Free, unlimited | Free, unlimited |
| CPU time per request | 10 ms | Default 30 s, configurable to 5 min |
| Memory per isolate | 128 MB | 128 MB |
| Worker size (uncompressed) | 64 MiB | 64 MiB ("no compressed size limit") |
| Asset file size / count | 25 MiB / 20,000 | 25 MiB / 100,000 |

Python on the Free plan: the pricing page states "By default, users have access to the Workers Free plan. The Workers Free plan includes limited usage of Workers..." with no Python carve-out anywhere in the Python docs. No page states the affirmative "Python Workers are available on the Free plan" sentence either — hence PARTIAL. Free-tier caveat for API+assets hybrid: with `run_worker_first`, requests over the free quota return 429 instead of falling back to asset serving ([billing page](https://developers.cloudflare.com/workers/static-assets/billing-and-limitations/)).

**F2.7 — First-party FastAPI demonstrations.** (a) GA blog post, 2026-09-21, with a FastAPI `asgi.entrypoint(app)` example: https://blog.cloudflare.com/python-workers-ga. (b) Official docs tutorial incl. serving a static frontend alongside FastAPI via the ASSETS binding: https://developers.cloudflare.com/workers/languages/python/packages/fastapi/ (updated 2026-08-28). (c) Examples repo: `github.com/cloudflare/python-workers-examples` (`fastapi` directory), referenced by both the docs page and the Python Workers docs.

## Implications for MAIC-DB M3 (agent assessment)

This section is assessment, not verified fact. Project constraints assumed: 1,100 rows; 3 MB SQLite artifact (`db/maicdb.sqlite`); `maicdb.query` on SQLAlchemy 2.0 + pyyaml, Python >= 3.11; static-first M3 website; $0 budget; deploys gated by PR review.

1. **A static M3 site does not need Cloudflare.** The M3 plan (GitHub Pages, static output) is unaffected by anything found: every named SSG (MkDocs, Sphinx, Astro, VitePress, Docusaurus, Hugo) also deploys to Cloudflare Pages or Workers with free, unlimited asset requests. Cloudflare is a viable fallback host at $0, not a reason to change the ADR.
2. **If M3 ever serves the query API online, FastAPI on Workers is real and documented.** GA since 2026-09-21; pydantic, pydantic-core, sqlalchemy, pyyaml all ship in the Pyodide distribution; uvicorn is not needed. This is the strongest reuse path for `maicdb.query` without a server.
3. **The 3 MB database fits both storage patterns.** As a static asset: 3 MB < 25 MiB per-file cap; readable from Python via the ASSETS binding; `sqlite3` is available per the stdlib exclusion list. In D1: 3 MB << 500 MB free-tier DB cap. The asset path keeps the artifact byte-identical to the repo's frozen releases; D1 would add an export/import step but is the platform-native query surface.
4. **The free-plan CPU limit is the main technical risk for an API worker, not size.** 10 ms CPU per request on Free against per-isolate SQLite loading is the number to benchmark before any ADR commit. Memory is capped at 128 MB per isolate; the artifact plus Pyodide overhead should fit, but this is untested.
5. **ADR wording should avoid two claims.** First, do not write "Cloudflare recommends Workers for new static sites" as a doc quote — no such sentence exists on the pages checked. Second, do not write "Pages is deprecated" — the primary record is convergence (2023-05-17) plus maintained Pages docs (Aug 2026) plus an active Pages→Workers migration guide (Oct 2026). Safer wording: "Cloudflare's current investment is in Workers with static assets; Pages remains supported with no announced sunset."
6. **Citation hygiene for the ADR.** The Pages `framework-configs` URL is dead; cite `pages/framework-guides/` and `pages/configuration/build-configuration/`. The Pyodide package-list URL keeps its historical typo: `packages-in-pyodide.html` (the corrected-spelling URL 404s).
